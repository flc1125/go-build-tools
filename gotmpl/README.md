# gotmpl

> Derived from OpenTelemetry `opentelemetry-go-build-tools` v0.30.0.

`gotmpl` generates files from Go
[templates](https://pkg.go.dev/text/template) and JSON data.

## Installation

```sh
go install github.com/flc1125/go-build-tools/gotmpl@latest
```

For source installation and Go requirements, see the
[repository installation guide](../README.md#installation).

## Usage

| Flag | Short form | Value |
| --- | --- | --- |
| `--body` | `-b` | Path to the template file. Required. |
| `--data` | `-d` | JSON data for the template. Use `{}` when you do not need template data. |
| `--out` | `-o` | Path to the output file. Required. |

### Example

1. Create `message.go.tmpl` with this content:

   ```go
   // Code generated by gotmpl. DO NOT EDIT.
   package {{ .pkg }}

   const Message = {{ printf "%q" .message }}
   ```

2. Generate `message.go`:

   ```sh
   gotmpl --body=message.go.tmpl --data='{"pkg":"example","message":"hello"}' --out=message.go
   ```

3. Read the generated file:

   ```go
   // Code generated by gotmpl. DO NOT EDIT.
   package example

   const Message = "hello"
   ```

The output directory must already exist. `gotmpl` replaces an existing output
file after it renders the template successfully.

### Errors

`gotmpl` returns a nonzero exit status if required paths are missing, JSON is
invalid, or template processing fails. A missing JSON field that the template
accesses causes an error. For example, the template above requires `pkg` and
`message`.

A template or JSON error leaves an existing output file unchanged.

## Background

Dependencies on internal packages in other modules can cause build failures
when those packages make incompatible API changes.

You can use `gotmpl` to generate shared, non-exported code in multiple Go
modules. We recommend a separate internal Go module for the templates, such as
`internal/shared`.

Use `go generate` to render the templates in each destination module:

```go
//go:generate gotmpl --body=../internal/shared/env.go.tmpl "--data={ \"pkg\": \"example\" }" --out=env.go
```

Paths in this directive are relative to the directory containing the Go source
file. The `gotmpl` executable must be available on `PATH`.
